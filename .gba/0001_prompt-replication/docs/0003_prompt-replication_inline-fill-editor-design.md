# Prompt Replication V2：句内填空编辑器设计

**日期：** 2026-08-03  
**状态：** 已完成交互设计，等待用户审核  
**所属功能：** `.gba/0001_prompt-replication`  
**影响范围：** Pattern Library 模式的变量编辑体验

## 1. 设计结论

Pattern Library 不再把动态变量渲染成传统表单。用户选择参考作品后，页面显示一段可以直接读懂的创作描述；需要修改的变量以彩色词槽嵌入句子，其他文字负责说明系统继承的视觉语言和内容机制。

示例：

> 沿用参考作品的极简线稿、强对比、大留白和冷幽默，创作一个关于【AI 创业】的冷笑话，用【程序员加班】作为情境，最后通过【模型又崩了】形成反转。

普通文字不可编辑。方括号中的内容在真实界面中显示为可编辑词槽，不显示方括号。系统在用户选择案例时自动填入一套人工审核的建议答案，用户可以直接生成，也可以只修改自己关心的词槽。

## 2. 目标

1. 让用户通过阅读完整句子理解每个变量的作用，不再在字段标签和参考图之间来回建立对应关系。
2. 把“继承什么”和“改变什么”放进同一段创作描述，不再使用独立说明卡片。
3. 把首屏编辑负担限制在 3 个核心词槽；确有必要的特殊 Pattern 最多 4 个。
4. 所有案例选择后都立即拥有一套可生成的建议值，不出现空白表单。
5. 保持 Pattern Registry、草稿恢复和隐藏 Prompt Compiler 的职责不变。

## 3. 非目标

- 本版不增加 AI 即时重填或“换一组”功能。
- 本版不自动抽取 Visual DNA 或 Content Pattern。
- 本版不向用户展示或开放编辑最终 Prompt。
- 本版不改变生成模型、生成 API、计费或任务记录结构。
- 本版不重新设计 Manual mode；自由提示词模式保持现状。

## 4. 核心交互

### 4.1 初始状态

用户选择一个已审核案例后：

1. 系统取得案例绑定的 `patternId`。
2. 系统载入该 Pattern 的句内填空模板。
3. 系统载入该案例的人工审核建议值。
4. 页面渲染一段完整创作描述，所有词槽均有值。
5. 只要其他生成条件满足，用户无需编辑即可点击生成。

### 4.2 编辑状态

- 点击词槽进入编辑状态。
- 输入内容时，词槽宽度随内容增长，并在达到最大宽度后停止增长。
- 词槽作为一个整体参与句子换行，不允许文字或边框被拆到两行。
- `Tab` 和 `Shift+Tab` 按视觉顺序切换词槽。
- `Enter` 在短文本词槽中完成本次编辑，不插入换行。
- `Escape` 恢复聚焦时的值并退出编辑。
- 用户修改后立即更新 Pattern 草稿；Compiler 使用最新值。

### 4.3 信息层级

编辑区域只保留：

1. 一段句内填空创作描述；
2. 必要的字段级错误信息；
3. 原有生成设置和生成按钮。

编辑区域不再显示：

- Pattern 名称和描述；
- 独立字段标签；
- 常驻帮助文字；
- 字符统计；
- “继承 / 改变”说明卡片；
- 完整 Prompt 查看入口。

## 5. Pattern 展示契约

### 5.1 Pattern 级模板

每个首期 Pattern 增加 `fillTemplate`。模板由自然语言和严格格式的变量标记组成：

```ts
fillTemplate:
  "沿用参考作品的极简线稿、强对比、大留白和冷幽默，创作一个关于{{topic}}的冷笑话，用{{setup}}作为情境，最后通过{{punchline}}形成反转。"
```

模板要求：

- 只能引用 Pattern `variables` 中已声明的 key；
- `variables` 中的每个变量必须且只能出现一次；本版不增加“隐藏变量”状态；
- 变量顺序就是键盘焦点顺序；
- 固定文案必须同时表达继承规则和内容机制；
- 总长度在填入最大合法值后不得超过 220 个中文字符；
- 不使用“请填写”“输入内容”等表单式措辞。

### 5.2 案例级建议值

建议值属于参考案例，而不是 Pattern。一个 Pattern 将来可以绑定多个案例，每个案例仍能提供符合自身语境、但与原主题明显不同的一套建议答案。

```ts
suggestedPatternValues: {
  topic: "AI 创业",
  setup: "程序员加班",
  punchline: "模型又崩了"
}
```

建议值要求：

- 覆盖模板引用的全部变量；
- 通过现有 Pattern Schema 类型、长度和枚举校验；
- 不复制参考作品的主体、场景、文案、账号或水印；
- 组合后语义完整，可以直接生成；
- 经过人工审核并随案例数据进入版本控制。

### 5.3 变量数量与类型

- 每个 Pattern 默认定义 3 个核心变量。
- 特殊 Pattern 最多定义 4 个变量，并需要在现有人工审核记录中说明必要性。
- 首期词槽支持 `short_text`、`enum` 和 `number`。
- `long_text` 不进入句内编辑器；相关信息应改写为固定创作约束，或拆成短变量。
- `topic` 继续作为必需的、无 Schema 默认值的核心变量；案例建议值负责初始填充。

## 6. 组件边界

### 6.1 `StyleRecreationEditor`

负责：

- 解析已通过 Schema 校验的 `fillTemplate`；
- 按模板顺序组合固定文字与词槽；
- 展示字段错误；
- 把用户输入通过 `onValueChange(key, value)` 交给上层。

不负责：

- 生成最终 Prompt；
- 读取参考图内容；
- 决定案例建议值；
- 调用生成 API。

### 6.2 `InlinePatternSlot`

独立词槽组件负责：

- 文本、枚举和数字的紧凑编辑；
- 内容宽度测量及最小、最大宽度约束；
- 键盘交互、聚焦状态和无障碍名称；
- 错误状态及紧邻错误信息。

### 6.3 Registry 与案例数据

- Pattern Registry 保存 `fillTemplate` 和变量定义。
- 案例数据保存 `suggestedPatternValues`。
- Registry 启动校验同时检查模板 token、变量数量和建议值完整性。

### 6.4 Prompt Compiler

Compiler 继续接收 `pattern + patternValues`，不读取或解析 `fillTemplate`。句子只是用户界面；Pattern、Creative Constraints 和结构化变量仍是生成事实来源。

## 7. 数据流

```text
用户选择案例
  → 读取 patternId + suggestedPatternValues
  → 恢复同版本用户草稿（存在时优先）
  → 渲染 fillTemplate + InlinePatternSlot
  → 用户修改结构化变量
  → Pattern Schema 校验
  → 隐藏 Prompt Compiler
  → 现有生成 API
```

优先级固定为：当前 Pattern 同版本草稿 > 案例建议值。旧版本草稿继续按现有版本策略处理，不允许旧 key 静默进入 Compiler。

## 8. 视觉规则

### 8.1 桌面端

- 创作句建议字号 `18px`，行高 `1.9–2.1`。
- 词槽最小宽度 `72px`，最大宽度 `240px`。
- 词槽使用浅黄、浅蓝等高亮底色和明确的底边界；相邻词槽颜色应可区分，但不承担类型语义。
- 编辑器宽度跟随现有 Composer，句子自然换行。
- 典型 3 词槽 Pattern 在当前桌面宽度下占 2–4 行。

### 8.2 移动端

- 创作句建议字号 `16px`，行高不低于 `1.8`。
- 单个词槽最大宽度为可用容器宽度。
- 页面和编辑器不得出现横向滚动。
- 词槽触控高度不低于 `44px`。
- 软键盘出现时，当前词槽不得被固定工具栏遮挡。

### 8.3 状态

- 默认：高亮底色清晰表示可编辑。
- Hover：边界或阴影轻微增强，不改变布局。
- Focus：显示高对比焦点环。
- Error：使用红色边界和相邻短错误文案；不能只靠颜色表达。
- Disabled：仅用于 Pattern 无效或案例未审核，并沿用“模板准备中”阻断逻辑。

## 9. 错误处理

- `fillTemplate` 引用未知变量：Registry 校验失败，该案例不可生成。
- 模板遗漏 Pattern 变量或重复引用：Registry 校验失败。
- 建议值缺失、类型错误或越界：案例不可生成，不回退到空表单或旧 Prompt。
- 用户清空必填词槽：词槽保留空状态并显示紧邻错误，生成按钮不可提交。
- Compiler 失败：保留用户当前词槽值，显示现有生成前错误，不泄露完整 Prompt。

## 10. 验收标准

### 10.1 数据完整性

- 首期 20 个 Pattern 的 `fillTemplate` 配置率为 100%。
- 首期已绑定案例的 `suggestedPatternValues` 配置率为 100%。
- 每个 Pattern 定义 3 个词槽；获准的特殊 Pattern 最多 4 个。
- 模板 token 与 Pattern 变量的一致率为 100%。
- 建议值通过 Schema 校验的比例为 100%。

### 10.2 交互

- 选择任何已审核案例后，空白词槽数量为 0。
- 任何词槽在默认状态下都不得占满整行。
- 用户可仅使用键盘按视觉顺序完成全部词槽编辑和提交。
- 用户修改任意词槽后，API 请求中的 Prompt 必须包含新值，不能继续使用建议值。
- Pattern 切换后，草稿恢复结果必须符合既有版本规则。

### 10.3 页面简化

Pattern Library 编辑区中以下元素数量必须为 0：

- 独立字段标签；
- 常驻帮助文字；
- 字符统计；
- Pattern 名称和描述；
- “继承 / 改变”卡片；
- 完整 Prompt 查看入口。

### 10.4 响应式与无障碍

- 在 `1440×900`、`1024×768`、`390×844` 和 `360×800` 四种视口下无横向溢出。
- 触控目标最小高度达到 `44px`。
- 每个词槽拥有由变量 label 提供的可访问名称。
- 错误信息通过 `aria-describedby` 与对应词槽关联。
- 焦点环在浅黄、浅蓝和页面背景上均清晰可见。

### 10.5 自动化验证

- 模板解析、未知 token、重复 token、遗漏 token 和顺序测试全部通过。
- 文本、枚举、数字词槽的输入及键盘测试全部通过。
- 默认建议值、用户草稿优先级和 Pattern 版本切换测试全部通过。
- Composer 提交测试证明 Compiler 接收最终结构化值。
- 现有 Prompt Compiler 确定性和长度测试保持通过。

## 11. 发布边界

本次实现只替换 Pattern Library 的变量呈现方式并补齐案例建议值。Manual mode、生成 API、模型选择、参考图上传、任务历史和计费逻辑均不得因本次改动产生行为变化。

“换一组”可以作为后续功能：由 AI 基于 Pattern 生成新的结构化建议值，并继续复用同一套句内填空组件。该能力不属于本次验收范围。
