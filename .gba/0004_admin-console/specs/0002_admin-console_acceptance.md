# Admin Console 验收规格

## 1. 验收范围与规则

- 对应设计：`0001_admin-console_spec.md`。
- 验收环境必须使用隔离数据库，不得以生产真实订单做破坏性测试。
- 固定账号：owner `iven_chloe@icloud.com`、1 个普通用户、1 个测试目标用户。
- 每个用例必须保留命令日志、API 响应或截图之一；涉及数据一致性的用例必须附数据库查询证据。
- P0 用例全部通过才可发布。P1/P2 不阻塞当前充值管理基线，但不得误标为已完成。

## 2. 发布阻断标准

以下任一项发生即验收失败：

1. 未登录或普通用户读取到任何后台业务数据。
2. 同一幂等键导致积分增加 2 次或以上。
3. 成功写操作缺失审计，或失败写操作残留积分/订单伪成功数据。
4. 撤回使任一余额小于 0。
5. owner 无法进入后台，或普通 admin 能执行 superadmin 撤回。
6. 测试、lint、生产构建任一非零退出。

## 4. 自动化测试最低集合

至少覆盖以下 12 个断言，并优先放在纯函数、service 与 route 层：

1. owner 邮箱大小写不敏感。
2. `SUPERADMIN_EMAILS` 逗号分隔与空格清理正确。
3. 无 session 返回 401。
4. 普通用户返回 403。
5. 充值积分下边界与上边界。
6. remark、reason、note 长度边界。
7. 页大小钳制为 1～100。
8. 串行重复幂等。
9. 并发重复幂等。
10. 充值事务任一步失败全回滚。
11. 撤回不产生负余额。
12. 成功写操作与审计一一对应。
