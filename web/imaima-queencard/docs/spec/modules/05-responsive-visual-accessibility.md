# 模块 05：响应式、视觉与无障碍

## 1. 模块目标

让生成工作台在桌面、平板和手机上保持同一任务顺序，同时针对设备重排导航、参数和结果。视觉延续 MM-Coincard，不把 Raphael 的桌面布局直接缩小，也不把移动端做成横向滚动的控制台。

## 2. 响应式断点

| 范围 | 导航 | 主区 | 结果列数 | 生成操作 |
| --- | --- | --- | --- | --- |
| `≥1280px` | 208px 完整侧栏，可主动折叠 | 24–32px 页面内边距，生成器与结果同屏优先 | 4 列 | 编辑器右下，非固定 |
| `768–1279px` | 72px 图标侧栏 | 20–24px 内边距；高级参数进入 Popover | 2 列 | 编辑器底部右侧 |
| `360–767px` | 无常驻侧栏，顶部菜单 + Drawer | 单列，16px 水平内边距 | 2 列 | 底部安全区上方 sticky bar |
| `<360px` 或 200% zoom | Drawer | 单列，12px 水平内边距 | 1 列 | 底部安全区上方 sticky bar |

页面必须在 390×844、768×1024 和 1440×900 三个基准 viewport 验收，并在 320px 宽或浏览器 200% zoom 下做补充检查。

## 3. 桌面布局

### 3.1 页面骨架

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 侧栏 208px   │ 顶部工具条                                  │
│              ├─────────────────────────────────────────────┤
│ 图片生成     │ 标题 + 来源标签                             │
│ 提示词库     │ 生成器：模式 / 参考图 / prompt / 参数 / CTA │
│ 生成历史     │ 当前任务或结果                              │
│ 积分 / 会员  │                                             │
│ 账户 / 积分  │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 页面主区最小宽度为 0，所有 flex/grid 子项允许收缩，避免长 prompt 撑出横向滚动。
- 内容最大宽度不强制固定为营销页窄栏；在 1440px 下利用可用宽度展示 4 张 3:4 结果。
- 生成器出现在标题下方，不插入大型案例摘要卡。
- 当前任务与结果紧接生成器，用户无需滚动超过一个 viewport 才看到首行结果。
- 历史视图使用同一主区，不叠加第二条顶栏。

### 3.2 侧栏

- 侧栏可以 sticky 或固定，但不得遮挡页面滚动条。
- 账户和积分固定在侧栏底部。
- 208px 宽度下文字完整；72px 宽度下只显示图标和 Tooltip。
- 侧栏自身内容超出高度时使用独立滚动区域，账户入口仍可访问。

## 4. 平板布局

- 侧栏默认折叠为 72px。
- 主标题不超过 32px。
- 参考图区域和 prompt 可以保持并排，但最小 prompt 宽度 320px；不足时改为上下布局。
- 参数行显示模型、画幅、数量和主按钮；分辨率及其他次级参数进入 Popover。
- 结果改为 2 列，保持真实画幅。
- 历史列表卡片使用单列，不并排显示详情面板。

## 5. 移动布局

### 5.1 顶栏

- 高度 56px。
- 左侧 44×44px 菜单按钮，中间紧凑 Wordmark，右侧积分或登录入口。
- 不显示桌面面包屑和多个顶部按钮。

### 5.2 生成器

顺序：

1. 页面标题和来源标签。
2. 两列等宽模式分段控件。
3. 参考图网格；3 张在 390px 内完整显示，不要求横向滚动。
4. prompt 输入，最小可见高度 120px。
5. 2 列参数网格：模型、画幅、张数、更多设置。
6. 错误、估价或状态信息。
7. 结果网格。

“更多设置”打开 bottom sheet 或 Dialog，不能使用超出屏幕的桌面 Popover。

### 5.3 底部生成栏

- 仅在编辑态显示。
- 包含预计积分和主按钮。
- 使用 `padding-bottom: env(safe-area-inset-bottom)`。
- 页面内容底部预留等于生成栏高度加安全区的空间。
- 滚动到底时最后一张结果、错误提示和历史“加载更多”不得被遮挡。
- 软键盘出现时生成栏不得覆盖当前输入；可以随 visual viewport 上移或在输入聚焦时降级为普通文档流。

### 5.4 移动结果动作

- 主下载按钮或更多菜单始终可见，不能只在 hover 时出现。
- 结果工具菜单使用 bottom sheet 或 DropdownMenu，触控目标不小于 44×44px。
- 结果 2 列；320px 或 200% zoom 下改为 1 列。

## 6. 视觉规范

### 6.1 页面层级

| 元素 | 规范 |
| --- | --- |
| 页面背景 | `#f6e0db` 或现有生成工作台的浅粉层次，不使用装饰性渐变 |
| 主编辑器 | 白色，1.5–2px 炭黑边框，18–24px 圆角，4px 硬阴影 |
| 结果卡 | 1–1.5px 炭黑或低透明边框，12–16px 圆角；不叠加厚卡片阴影 |
| 主按钮 | `#ef724f`，炭黑文字/边框，2px 硬阴影 |
| 当前模式/导航 | `#e7db4c`，炭黑边框 |
| 成功 | `#ace2df`，同时有文字/图标，不只靠颜色 |
| 来源信息 | `#84bfff` 标签 |
| 错误 | 现有品牌体系内的红色派生色，必须配文字 |
| 焦点 | 2–4px 可见 outline，优先 `#ef724f`，与组件边界留 2px offset |

### 6.2 字体与字号

- 页面标题：桌面 32–36px，移动 24–28px，字重 800。
- 区域标题：18–24px。
- 正文：14–16px。
- 参数和辅助信息：最低 12px；关键状态最低 14px。
- 不使用 Alfa Slab One 渲染长中文标题。
- 数字和单位保持在同一行，例如 `20 积分`。

### 6.3 间距

- 4px 基准网格。
- 页面区域间距 24–32px。
- 编辑器内部 12–20px。
- 控件间距 8–12px。
- 图标与文字 6–8px。
- 禁止通过大量空白把编辑器推到首屏下方。

### 6.4 动效

- 模式切换和折叠 150–220ms。
- skeleton 可以使用低对比度 shimmer，但不得导致 layout shift。
- 结果出现可以淡入 160–240ms，不逐张延迟超过 400ms。
- 尊重 `prefers-reduced-motion: reduce`：关闭位移动画、循环 shimmer 和非必要缩放。
- 不复制 Raphael 的发光或宣传动画。

## 7. 键盘交互

用户必须仅用键盘完成：

1. 打开生成页。
2. 切换模式。
3. 选择或删除参考图；文件选择器本身由浏览器处理。
4. 输入 prompt。
5. 选择模型、画幅、张数和分辨率。
6. 提交生成。
7. 打开历史并选择任务。
8. 下载结果、设为参考、引用 prompt、重新生成。
9. 完成参考图替换 Dialog。

Tab 顺序遵循视觉顺序。禁止正数 `tabIndex`。Popover、Dialog 和 Drawer 关闭后焦点回到触发控件。

## 8. 语义与屏幕阅读器

- 页面只有一个 `h1`：“AI 图片生成器”。
- 模式使用 Tabs 或 RadioGroup 语义，报告名称和选中状态。
- 参考图列表使用可理解的列表和按钮名称，例如“删除参考图 2”。
- 模型、比例、张数和分辨率有可见 label 或 `aria-label`。
- 生成按钮名称包含动作，不只读出积分数字。
- 任务状态区域使用 `aria-live="polite"`。
- 失败区域使用 `role="alert"`。
- Progress 若没有真实百分比，使用不确定状态，不伪造 `aria-valuenow`。
- 结果图片 alt 描述为“任务 <短 ID> 的第 N 张生成结果”；不把完整 prompt 塞进 alt。
- 只有图标的操作提供 `aria-label` 和 Tooltip。

## 9. 触控与对比度

- 所有主要触控目标至少 44×44 CSS px。
- 相邻触控目标至少有 8px 可点区域间距，或通过容器保证不会误触。
- 正文与背景对比度不低于 4.5:1。
- 大字不低于 3:1。
- 图标、边框和焦点等非文本控件不低于 3:1。
- 禁止只靠黄、绿、红颜色区分模式和状态；必须同时有文字、图标或形状。

## 10. 可访问性质量门槛

- axe serious 和 critical 问题为 0。
- 六种状态分别检查：空白文生图、参考图 seed、生成中、部分成功、失败、替换 Dialog。
- 320px 或 200% zoom 下不得同时出现水平和垂直二维滚动。
- 页面所有可见交互都有可见焦点。
- 错误发生后焦点移动到错误摘要或通过 live region 被播报，但不抢走正在输入的焦点。

## 11. 性能与稳定性目标

在本地或预生产的移动 Lighthouse 条件下：

- Performance ≥80。
- Accessibility ≥95。
- LCP ≤2.5s。
- CLS ≤0.1。
- INP ≤200ms。

生成结果图片使用合适尺寸、懒加载和占位比例，避免原图一次性撑开布局。性能门槛不允许以移除真实功能或只测试空白页面的方式通过。
