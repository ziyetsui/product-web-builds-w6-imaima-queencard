# 模块 02：双模式生成器

## 1. 模块目标

在同一生成器中提供真实可用的纯文生图和参考图生成。用户能看懂当前模式、模型能力、参考图是否参与请求、预计消耗多少积分，以及哪些参数会进入本次任务。

## 2. 模式定义

| 产品模式 | API capability | 参考图数量 | 默认模型 | 默认画幅 |
| --- | --- | --- | --- | --- |
| 纯文生图 | `text-to-image` | 必须为 0 | `gpt-image`，显示名 `GPT Image 2` | `1:1` |
| 参考图生成 | `image-edit` 或 `image-to-image` | 1–3 | `gpt-image-2-edit`，显示名 `GPT Image 2` | `3:4` |

“参考图生成”是用户可见名称。服务端仍保留 `image-edit` 与 `image-to-image`，用于匹配不同 provider 路由。

## 3. 模式切换

### 3.1 切换到纯文生图

1. 参考图从请求中排除，但在当前编辑会话中暂存。
2. 用户切回参考图生成时，恢复原图片顺序。
3. 如果当前模型不支持纯文生图，系统自动选择默认文生图模型。
4. 页面显示一次轻量 Toast：“已切换为 GPT Image 2 文生图模型”。
5. 默认画幅只在用户尚未手动选择画幅时改为 `1:1`。
6. prompt、输出数量和分辨率保持不变，除非新模型不支持当前值。

### 3.2 切换到参考图生成

1. 若暂存区有 1–3 张图，立即恢复并允许提交。
2. 若没有参考图，显示上传区，生成按钮禁用。
3. 如果当前模型不支持图片输入，系统选择默认编辑模型并提示。
4. 默认画幅只在用户尚未手动选择时改为 `3:4`。
5. prompt 不得因切换模式而清空。

### 3.3 模式与数量的服务端真值

客户端显示不能替代服务端校验：

- `text-to-image` 请求携带任何参考图时返回 400。
- `image-edit` 或 `image-to-image` 请求为 0 张参考图时返回 400。
- 请求使用不支持当前 capability 的模型时返回 400。
- 禁用模型和未知模型返回 400。
- 服务端不得静默把文生图降级为图生图，或反向降级。

数据库不新增独立 mode 字段。任务的产品模式按 capability 唯一派生：`text-to-image → text-to-image`；`image-edit` 或 `image-to-image → image-to-image`。历史、任务详情和重新生成都使用该映射，不能从参考图是否临时可用反推。

## 4. 生成器信息结构

从上到下顺序固定为：

1. 模式分段控件。
2. 参考图区；纯文生图时收起为一行“添加参考图并切换模式”的次级入口。
3. 提示词输入区。
4. 模型、画幅、张数、分辨率和高级设置。
5. 服务端积分预估与唯一主按钮。

桌面端参考图和 prompt 可以并排；移动端必须上下排列。参数不得占用一张独立大卡。

## 5. 提示词

### 5.1 基本规则

- 去除首尾空白后长度必须为 1–2000 个 Unicode code point；前后端统一按 `Array.from(prompt).length` 等价规则计数。
- 空提示词时生成按钮禁用，服务端同时返回 400。
- 2001 字及以上时前端显示剩余字数为负的错误状态，禁止提交；服务端不得静默截断。
- 输入法组合期间不得提前触发长度修正或提交。
- 从案例进入时保留当前结构化中文提示词，不自动翻译。
- 任务提交后保存一份不可变 prompt 快照。

### 5.2 AI Enhance

当前 `aiEnhance` 只被保存为布尔值，没有调用提示词增强服务；因此本版本不显示 AI Enhance 开关。不得保留一个看似可用但不改变 provider 请求的控件。

未来重新引入时必须单独定义：原 prompt、增强后 prompt、用户确认、计费和失败回退。本规格不预留虚假 UI。

## 6. 参考图

### 6.1 支持范围

- 格式：JPEG、PNG、WebP。
- 数量：1–3 张。
- 原始单张文件上限 10 MB；进入 handoff 和创建请求前规范化到每张不超过 800 KiB，规则见模块 01。
- 每张图片显示缩略图、顺序、替换和删除操作。
- 重复 URL 或同一 handoff 资源只保留一次。
- 图片读取失败时标记具体槽位，不影响其他已验证图片。

### 6.2 第四张图片

已有 3 张参考图时，用户添加新图：

1. 不得静默忽略，也不得自动替换第一张。
2. 打开“替换参考图”Dialog。
3. Dialog 显示 3 个现有槽位和新图片预览。
4. 用户选择一个槽位后才替换；关闭 Dialog 保持原状。
5. 所有选择控件可用键盘操作，并有清楚的选中状态。

### 6.3 从结果设为参考

- 用户在结果图片上选择“设为参考”后，生成器切换为参考图生成。
- 当前不足 3 张时把结果加到末尾。
- 已满 3 张时使用同一替换 Dialog。
- 添加动作本身不创建新任务。
- 下一次创建任务的 payload 必须包含新的参考图，不能只改变缩略图。

## 7. 模型选择

### 7.1 能力驱动配置

模型配置增加 `text-to-image` capability。每个模型 ID 只声明一个 capability；同一品牌若支持多种模式，使用不同模型 ID 和相同显示名。界面只展示 `enabled=true` 且 capability 与当前模式匹配的模型。

本版本最低配置：

| 模型 ID | 显示名 | 能力 | 最大输出数 | 基础积分 | 支持分辨率 |
| --- | --- | --- | --- | --- | --- |
| `gpt-image` | GPT Image 2 | `text-to-image` | 4 | 4 积分/张 | `auto`、`1k`、`2k` |
| `gpt-image-2-edit` | GPT Image 2 | `image-edit` | 4 | 5 积分/张 | `auto` |
| `gemini-3.1-flash-edit` | Gemini 3.1 Flash | `image-edit` | 1 | 5 积分/张 | `auto`、`1k`、`2k`、`4k` |
| `seedream-5-edit` | Seedream 5.0 | `image-edit` | 1 | 4 积分/张 | `auto`、`1k`、`2k` |
| `doubao-seedream-5-edit` | Doubao Seedream 5.0 | `image-edit` | 1 | 4 积分/张 | `auto`、`1k`、`2k` |
| `viduq2-i2i` | Vidu Q2 | `image-to-image` | 1 | 使用现有按分辨率和参考图数量计价 | `auto`、`2k`、`4k` |

`gpt-image` 目前在价格配置中存在但处于禁用状态。本版本把它启用、显示名改为 GPT Image 2、基础价锁定为 4 积分/张，并把 provider 路由改为 OpenAI-compatible image generation；不得把 `gpt-image-2-edit` 在零参考图时直接发送到 edit endpoint。

### 7.2 模型切换约束

- 新模型最大输出数小于当前张数时，张数自动降到上限，并显示 Toast。
- 新模型不支持当前分辨率时，改为 `auto`，同时显示说明。
- 选择模型时展示显示名、能力标签、单张起始积分和最大张数。
- 不把 provider 内部名称或 endpoint 暴露给普通用户。
- 客户端过滤和服务端 allowlist 必须使用同一配置来源，避免两套判断漂移。

## 8. 画幅、张数与分辨率

### 8.1 画幅

继续支持现有 8 种比例：

`1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`2:3`、`3:2`、`21:9`。

服务端对未知比例返回 400，不应再默默回退；只有完全缺省时使用模式默认值。

### 8.2 输出数量

- 全局范围 1–4。
- 每个模型可以设置更小上限。
- 数量控件只展示当前模型支持的值。
- 用户提交伪造的更大数量时服务端返回 400，不静默截断。
- 本次任务保存用户实际请求数量。

### 8.3 分辨率

全局枚举为 `auto`、`1k`、`2k`、`4k`，但模型菜单只展示 7.1 表中明确支持的值。模型配置增加 `supportedResolutions` 和 `defaultResolution`；客户端菜单、estimate 和 create 共用该配置。未知值或模型不支持的值返回 400。

### 8.4 Fast Mode

当前 `fastMode` 不改变 provider 路由或请求，本版本不显示 Fast Mode。未来引入必须有可验证的模型、队列或计价差异。

## 9. 积分预估

### 9.1 数据来源

生成按钮显示的积分来自 `POST /api/v1/image-generations/estimate`，不能使用客户端 `基础价 × 张数` 作为最终值。该接口允许匿名调用，因为只计算公开模型价格且没有副作用；请求使用严格 schema、3.5 MB body 上限，并且不接受 prompt 全文或图片内容，只接受 mode、model、张数、分辨率和参考图数量。创建任务仍必须登录。

预估输入必须与创建任务输入一致：

- mode/capability
- model
- output count
- resolution
- reference image count
- 未来存在的其他计价维度

### 9.2 更新时机

- 上述计价参数变化后 300 ms debounce。
- 最近一次合法修改后的 500 ms 内更新显示。
- 新请求发出时取消或忽略旧请求，避免旧结果覆盖新值。
- 预估中显示骨架或 spinner，不显示 0 积分。
- 预估失败时生成按钮禁用并显示“暂时无法计算积分，请重试”。

### 9.3 一致性

同一 payload 必须满足：

```text
UI 预估积分
= estimate API estimatedCredits
= generation_tasks.requested_credits
= credit_holds 冻结积分
```

最终结算可以因部分成功小于预估，但不得大于预估。

## 10. 提交与按钮状态

生成按钮文字：

- 可提交：`生成 · <N> 积分`
- 估价中：`计算积分中`
- 创建请求中：`正在提交`
- 任务运行中：`正在生成`
- 未登录：仍显示积分，点击后进入登录恢复流程
- 积分不足：`积分不足 · 需要 <N>`，旁边或错误区提供“获取积分”

生成按钮禁用条件：

- prompt 不合法。
- 参考图模式没有 1–3 张合法图片。
- 没有可用兼容模型。
- 画幅、张数或分辨率不合法。
- 估价中或估价失败。
- 创建任务请求尚未返回。
- 当前页面已锁定在同一个运行中任务，且本版本不允许并发提交。

单次点击只能产生一个 POST 和一个任务。按钮必须在请求发起前同步进入禁用状态，阻止双击。

## 11. 草稿与任务快照

- 用户编辑时持续保存草稿。
- 点击生成后，把 prompt、参考图、模型、模式、画幅、张数、分辨率和来源冻结为任务快照。
- 任务运行期间生成器显示只读快照，避免用户误以为修改会影响已提交任务。
- 终态后用户点击“继续创作”才恢复为可编辑草稿。
- 失败、401、402 或 provider 错误不得清空草稿。
