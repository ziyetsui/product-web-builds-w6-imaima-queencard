## 背景

imaima queencard 后续会有一部分售卖方式不走公开自助支付页，而是通过社媒引流完成：

1. 用户在小红书、微信、社群或私域咨询。
2. 用户通过线下或第三方方式付款给运营者。
3. 运营者把网站链接发给用户。
4. 用户注册或登录网站。
5. 管理员在后台看到新用户记录。
6. 管理员核对付款后给用户加积分。
7. 用户回到前台即可看到充值后的积分并开始使用。

因此需要一个后台充值管理系统，作为人工销售和线上积分系统之间的履约入口。

## 目标

- 建立一个安全、可审计、低摩擦的人工充值后台。
- 管理员可以快速找到刚注册或已付款用户，并给用户充值积分。
- 人工充值必须进入现有积分账本，让用户前台余额、消费、历史记录保持一致。
- 管理员的每一次加积分、撤回、备注修改都可追溯。
- 不影响现有 Stripe/Creem 自动支付、webhook 履约和用户前台生成链路。

## 非目标

- 不在本期实现在线收款、二维码支付或自动识别转账。
- 不替代 Stripe/Creem 的自动支付 webhook。
- 不在本期实现 CRM、私域会话、订单分销结算或发票系统。
- 不允许管理员直接改写用户余额总数字段。
- 不在本期重做完整管理后台所有菜单，只聚焦用户充值管理。

## 角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 用户 | 从社媒付款后获得链接并注册登录的人 | 查看前台积分余额和积分历史 |
| 运营管理员 | 日常处理付款核对、备注、充值 | 搜索用户、查看充值信息、发放预设积分、写备注 |
| 超级管理员 | 管理高风险操作和系统配置 | 拥有运营管理员权限，可撤回人工充值、导出日志、配置充值档位 |

## 核心流程

### P0 流程：人工销售充值

```text
社媒沟通 -> 用户付款 -> 运营发网站链接 -> 用户注册/登录
-> 后台出现新用户行 -> 管理员搜索/定位用户
-> 管理员选择充值档位或输入积分 -> 二次确认
-> 系统写入积分包和积分流水 -> 前台余额实时更新
```

### P0 流程：管理员查找新用户

1. 管理员进入后台 `用户充值管理`。
2. 默认按注册时间倒序展示用户。
3. 管理员可用邮箱、用户名、用户 ID、邀请码搜索。
4. 管理员看到用户的注册时间、当前可用积分、已消耗积分、是否付费、备注。
5. 管理员根据付款记录识别目标用户。

### P0 流程：快捷充值

1. 管理员点击用户行的快捷按钮，如 `+100` 或 `+500`。
2. 系统弹出确认框，展示用户邮箱、充值积分、有效期、备注输入框。
3. 管理员确认后系统发放积分。
4. 表格该行的可用积分立即增加。
5. 用户前台积分余额接口返回新余额。

### P1 流程：自定义充值

1. 管理员点击“自定义充值”。
2. 输入积分数量、付款渠道、付款金额、外部付款凭证、备注。
3. 系统校验积分数量和备注。
4. 管理员确认后发放积分并写审计记录。

### P1 流程：撤回人工充值

1. 超级管理员进入用户充值明细。
2. 找到某笔人工充值。
3. 点击“撤回未使用积分”。
4. 系统仅撤回该笔充值中尚未使用、未冻结的积分。
5. 已使用部分不让余额变负，标记为需要人工处理。

## 需求清单

### 用户列表与搜索

- FR-001：后台必须展示用户列表，默认按注册时间倒序。
- FR-002：列表必须展示邮箱、用户名或昵称、用户 ID、状态、角色、注册时间。
- FR-003：列表必须展示积分摘要：可用积分、冻结积分、已消耗积分、总获得积分。
- FR-004：列表必须展示人工充值摘要：最近充值时间、最近充值积分、最近操作管理员。
- FR-005：搜索框支持邮箱、用户名、用户 ID、邀请码或外部付款备注模糊搜索。
- FR-006：支持分页，默认每页 50 个用户。
- FR-007：支持筛选新注册用户、已充值用户、未充值用户、低余额用户。

### 人工充值

- FR-008：管理员可以给指定用户增加积分。
- FR-009：系统必须提供快捷档位，首期至少包括 `+100`、`+500`。
- FR-010：系统必须支持自定义积分数量。
- FR-011：每笔充值必须记录操作原因或备注。
- FR-012：每笔充值必须记录操作管理员、操作时间、目标用户、积分数量。
- FR-013：每笔充值必须生成积分包，并进入用户可用余额。
- FR-014：每笔充值必须生成积分流水，用户前台积分历史可见。
- FR-015：人工充值默认有效期为 365 天，后续可配置。
- FR-016：系统不得允许充值 0 或负数积分。
- FR-017：系统必须有二次确认，防止误点快捷按钮。

### 付款信息记录

- FR-018：人工充值可以记录付款渠道，如微信、支付宝、银行转账、其他。
- FR-019：人工充值可以记录付款金额和币种。
- FR-020：人工充值可以记录外部付款凭证号、截图说明或人工订单号。
- FR-021：同一外部付款凭证号不应被重复用于成功充值，除非超级管理员确认覆盖。
- FR-022：付款凭证不必对用户可见，但必须对管理员可审计。

### 备注

- FR-023：管理员可以修改用户级备注。
- FR-024：充值时可以写充值备注。
- FR-025：备注修改必须写入审计日志。
- FR-026：列表中展示短备注，详情中展示完整备注历史。

### 撤回与纠错

- FR-027：超级管理员可以撤回人工充值的未使用积分。
- FR-028：撤回不得导致用户可用积分为负。
- FR-029：如果用户已经使用部分或全部积分，系统必须显示已使用数量和剩余可撤回数量。
- FR-030：撤回操作必须要求填写原因。
- FR-031：撤回操作必须写入积分流水和审计日志。

### 权限与安全

- FR-032：只有管理员可以访问后台充值管理。
- FR-033：普通管理员不能撤回充值、导出日志或修改充值档位。
- FR-034：超级管理员可以进行高风险操作。
- FR-035：所有后台接口必须服务端校验权限，不能只依赖前端隐藏按钮。
- FR-036：后台页面不得泄露支付密钥、供应商 secret 或用户密码。

### 用户前台联动

- FR-037：充值成功后，用户前台余额接口必须立即反映新余额。
- FR-038：用户前台积分历史必须能看到人工充值记录。
- FR-039：用户正在生成任务时，充值不应破坏已有冻结积分。
- FR-040：用户余额计算必须继续基于积分包和积分流水，不新增孤立余额字段。

## 验收标准

- AC-001：用户注册后，管理员能在后台用户列表看到该用户。
- AC-002：管理员搜索邮箱能定位到目标用户。
- AC-003：管理员点击 `+500` 并确认后，用户可用积分增加 500。
- AC-004：充值成功后生成一条 `SYSTEM_ADJUST` 或等价人工充值流水。
- AC-005：用户前台余额接口展示充值后的余额。
- AC-006：刷新后台页面后，用户行仍显示最新余额和最近充值信息。
- AC-007：重复提交同一个充值请求不会重复加积分。
- AC-008：非管理员访问后台充值 API 返回 403。
- AC-009：撤回人工充值只撤回未使用积分，不产生负余额。
- AC-010：审计日志能查到谁在什么时间给哪个用户加了多少积分。

## 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 管理员误点快捷充值 | 用户余额错误 | 二次确认、审计日志、超级管理员撤回 |
| 用户付款身份和注册邮箱不一致 | 找不到用户或充错人 | 支持备注、外部付款凭证、搜索多字段 |
| 重复提交导致重复充值 | 账务错误 | 使用幂等键和唯一约束 |
| 人工充值绕过自动支付账本 | 用户前台余额不一致 | 复用 `credit_packages` 和 `credit_transactions` |
| 普通管理员滥用充值权限 | 资金风险 | RBAC、操作限额、审计、导出 |
