## 1. 产品概述

### 1.1 一句话定位

MM-Coincard 是一个以爆款案例为起点、同时支持纯文生图与参考图生成的小红书视觉创作工作台：用户从提示词库选择案例，进入统一生成页面确认参数，等待任务完成，并继续下载、复用或迭代结果。

### 1.2 目标用户

- 需要快速复用小红书爆款视觉结构的内容创作者。
- 不熟悉复杂模型参数，但能描述主题、标题和副标题的副业博主。
- 需要在多个模型之间比较质量、成本和速度的高频创作者。
- 已有参考图，希望保持画面结构、风格或角色一致性的用户。
- 没有参考图，希望直接从文字开始创作的用户。

### 1.3 本次改版解决的问题

当前 `/generated` 已具备创建任务、轮询、历史搜索、结果下载与复用等真实能力，但页面把顶部工具条、会话栏、超大标题、来源摘要和生成器同时放在首屏，导致主要任务被多个视觉层级分散。本次改版采用 Raphael 的高效工作台骨架，让生成器成为首屏唯一主角；同时保留 MM-Coincard 的粉色画布、黑色描边、硬阴影和橙黄强调色，不复制 Raphael 的深色皮肤、品牌资产、文案或专有视觉。

当前服务端强制至少一张参考图，模型配置也只有图片编辑或图生图能力。本版本必须打通纯文生图，不允许仅增加一个没有真实服务端能力的切换按钮。

### 1.4 核心用户路径

```text
/prompts 选择案例或编辑 seed
  → /generated 恢复提示词、参考图、模型与来源
  → 用户选择纯文生图或参考图生成
  → 服务端估算积分
  → 用户点击生成
  → 创建任务并冻结积分
  → queued / generating
  → completed / partial_success / failed
  → 下载、设为参考、引用提示词、重新生成或查看历史
```

关键约束：从 `/prompts` 跳转到 `/generated` 只恢复草稿，不创建任务、不冻结积分、不调用模型。只有用户在生成页明确点击“生成”后，系统才创建任务。

## 2. App 功能

本规格按六个面向用户的功能域拆分。每个模块文档说明用户动作、系统响应、状态、边界和失败处理。

### 2.1 路由、入口与 seed 交接

[查看详细规格：路由、入口与 seed 交接](./modules/01-routing-and-seed-handoff.md)

`/prompts` 继续作为产品主入口和案例选择页，`/generated` 作为生成工作台。系统必须兼容现有案例参数和旧任务链接，同时停止在 URL 中重复写入三套参考图参数。静态案例图片可以使用站内路径交接；本地上传的图片字节不得进入 URL、地址栏、浏览历史或分析日志。

### 2.2 双模式生成器

[查看详细规格：双模式生成器](./modules/02-dual-mode-composer.md)

生成器提供“纯文生图”和“参考图生成”两个明确模式。纯文生图发送零张参考图；参考图生成要求 1–3 张图片。模型列表根据模式实时过滤，积分预估由服务端返回，提示词、画幅、张数和分辨率继续使用当前真实能力。

### 2.3 任务生命周期与结果动作

[查看详细规格：任务生命周期与结果动作](./modules/03-task-lifecycle-and-results.md)

任务必须完整覆盖 `queued`、`generating`、`completed`、`partial_success` 和 `failed`。界面在终态停止轮询，完整成功、部分成功和失败分别展示不同结算信息。每张结果提供安全下载、设为参考和更多动作；重新生成必须创建新任务，不能覆写原任务。

### 2.4 历史、积分与账户上下文

[查看详细规格：历史、积分与账户上下文](./modules/04-history-credits-and-account.md)

桌面侧栏提供生成、提示词库、历史、积分和会员入口，并展示真实账户与可用积分。历史只显示当前用户数据，支持搜索、分页与从任务恢复编辑。积分不足必须在创建任务前阻断，并提供前往积分或会员页面的明确入口。

### 2.5 响应式、视觉与无障碍

[查看详细规格：响应式、视觉与无障碍](./modules/05-responsive-visual-accessibility.md)

桌面端采用固定侧栏和宽工作台，平板端收起为图标侧栏，移动端改为单列创作流和抽屉式导航。移动端不是桌面布局的缩小版。所有关键操作必须满足触控、键盘、焦点、对比度和状态播报要求。

### 2.6 技术架构与数据契约

[查看详细规格：技术架构与数据契约](./modules/06-architecture-and-data-contracts.md)

现有 `/generated/page.tsx` 约 1,760 行，混合 URL 解析、任务查询、历史、草稿、派生状态和大量 JSX。本版本把路由入口、状态编排、壳层、生成器和结果流拆开，但保留现有 API URL、任务状态名、数据表和 `/prompts` 的公共生成器入口。纯文生图使用现有 GPTProto/OpenAI generation 能力，不新建独立后端服务，也不做数据库迁移。

## 3. 视觉风格

### 3.1 设计方向

采用“Raphael 骨架 × MM-Coincard 视觉”。复制的是信息架构和交互效率：生成器上移、参数压缩、结果紧邻、跨任务导航进入侧栏；不复制 Raphael 的深色主题、具体图标、素材、文案、品牌标识、动画或宣传模块。

### 3.2 现有视觉事实

| 视觉元素 | 现有代码事实 | 本版本用法 |
| --- | --- | --- |
| 主字体 | Manrope | 正文、参数、按钮、状态与数据 |
| 展示字体 | Alfa Slab One | 仅用于少量品牌或展示标题，不用于长中文标题 |
| 品牌手写字体 | Pinyon Script | Wordmark 中的 `Q` 或少量品牌点缀 |
| 画布粉 | `#f6e0db` | 工作台背景与移动端主画布 |
| 炭黑 | `#1a1714` | 正文、描边、图标和硬阴影 |
| 白色 | `#ffffff` | 编辑器、结果工具条、Popover 与 Dialog |
| 南瓜橙 | `#ef724f` | 主按钮、运行状态与焦点强调 |
| 柠檬黄 | `#e7db4c` | 已选模式、当前导航和关键标签 |
| 海盐绿 | `#ace2df` | 成功状态、次级信息与正向提示 |
| 天空蓝 | `#84bfff` | 来源案例、参考图和信息标签 |
| 薰衣草紫 | `#e69dff` | 会员或次级品牌点缀；不得成为主背景 |
| 品牌阴影 | 2px、4px、6px、10px 炭黑硬阴影 | 主编辑器使用 4px；小按钮 2px；禁止在每张子卡上叠加厚阴影 |
| 全局圆角 | CSS token `--radius: 47px`，现有工作台多用 18–24px | 大容器 18–24px；按钮 10–14px 或胶囊；图片 12–16px |

### 3.3 视觉层级

1. 首屏第一层是生成器，包括模式、参考图、提示词和生成按钮。
2. 第二层是当前任务或本次结果；结果出现后不移动到独立页面。
3. 第三层是历史、积分和会员等跨任务入口，位于侧栏或移动抽屉。
4. 来源案例只显示为紧凑标签和返回入口，不再占用一张大型摘要卡。
5. 桌面标题保持 28–36px 范围；不得继续使用当前接近营销页的超大标题。
6. 同一屏不得同时出现两个同等强调的橙色主按钮。
7. 禁止装饰性渐变作为工作台背景；结果图片本身不受此限制。

### 3.4 组件原则

- 优先复用现有 shadcn/Radix `Button`、`Dialog`、`Popover`、`Select`、`Tabs`、`Tooltip`、`Progress`、`ScrollArea` 和 `Toast`。
- 图标使用 `lucide-react`，不在按钮中使用表情符号作为正式图标。
- 所有只有图标的按钮必须有可读 `aria-label` 和 Tooltip。
- 页面只保留一个主卡片层级。参数分组通过边框、间距和 Popover 表达，不套多层 Card。

## 4. 本版本交付内容

### 4.1 包含

1. 重做 `/generated` 的页面骨架、侧栏、工具条、生成器和结果区。
2. 保留 `/prompts → /generated` 的两阶段用户路径。
3. 兼容 `/generated/[taskId]` 和已有 seed 参数别名。
4. 新增真实纯文生图能力，默认使用启用且支持该模式的模型。
5. 保留 1–3 张参考图的图生图能力。
6. 明确的模式切换、模型能力过滤和不兼容模型服务端拒绝。
7. 服务端积分预估接入生成按钮。
8. `queued`、`generating`、`completed`、`partial_success`、`failed` 五种状态。
9. 终态停止轮询，避免骨架闪烁和无效请求。
10. 完整成功、部分成功和失败的真实积分结算反馈。
11. 结果安全下载、设为参考、提示词复用和真实重新生成。
12. 参考图达到 3 张时的明确替换流程。
13. 历史搜索、分页或加载更多、当前用户隔离和任务恢复。
14. 真实账户、可用积分、积分页和会员页入口。
15. 积分不足时在创建任务前阻断并提供获取积分入口。
16. 桌面、平板和移动端响应式布局。
17. 键盘、焦点、状态播报、对比度和触控尺寸要求。
18. 把路由级巨型页面拆成职责明确的组件、hook 和纯派生函数。
19. 规范化 seed URL；本地图片通过 IndexedDB handoff 交接并压缩，图片字节不进入地址栏。
20. task 与 credit hold 同事务创建；资产、终态和积分结算同事务完成，并有唯一补偿路径。
21. 必要的单元、组件、API 和集成测试。
22. 实施后的真实浏览器截图、API 响应和数据库状态验收证据。

### 4.2 不包含

- 不重做 `/prompts` 的案例网格、排序、搜索或视觉风格。
- 不新建 `/dashboard`、`/account` 或完整账单中心。
- 不重做 `/pricing`、`/credits`、登录、注册、支付、Webhook 或 Admin。
- 不实现 Raphael 的 Image Tools、Get Inspired、模板市场或视频生成。
- 不复制 Raphael 的深色视觉、素材、品牌标识、宣传条或具体文案。
- 不实现未接通的 AI Enhance 和 Fast Mode；在服务端具有真实语义之前不得在新生成器中显示为可操作功能。
- 不新增 Style、Color、Lighting、Composition 等没有模型契约的装饰性选项。
- 不接入 APIYI fallback。
- 不引入 durable queue、任务取消或服务端工作进程。
- 不解决支付退款、积分并发、Customer 唯一性和积分过期 cron 等独立后端问题。
- 不新增对象存储；provider URL 和生成资产持久化另立项目处理。
- 不新增业务 Analytics 事件。
- 不迁移到新的全局状态管理方案，不重写全部 TanStack Query/Zustand 使用方式。
- 不删除旧数据库表、旧组件 renderer 或与本功能无关的死代码。
- 不改变现有任务状态字符串、API URL 和数据库表名。

### 4.3 已知前置与后续问题

- 当前新用户礼包只有 2 积分，而启用模型的最低单张价格高于礼包。该问题会影响首次生成，但本次生成页改版不修改礼包策略；上线前必须由独立的积分/增长规格决定提高礼包、提供免费试用模型或调整价格。
- 当前生成任务由 Next.js `after()` 驱动，不是耐久队列。本版本只保证页面状态正确，不声称解决进程中断恢复。
- 当前生成资产可能直接保存 provider URL 或 Data URI。本版本保证本地图片字节不进入 URL，但不声称完成永久资产存储。

## 5. 验收标准

完整验收矩阵见 [ACCEPTANCE.md](./ACCEPTANCE.md)。

验收执行规则：

- 面向用户的每项功能必须有真实浏览器截图。
- 生成、积分、用户隔离等行为必须同时提供真实 API 响应与关键数据库状态。
- `build` 成功、测试通过、HTTP 200、日志中的“success”或静态占位图都不能单独证明功能通过。
- 证据执行时统一存放在 `w6/evidence/acceptance/`，本次仅定义标准，不提前伪造证据。
